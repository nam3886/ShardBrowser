# Creator on the ShardBrowser fork: M0-M2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the `creator-spike` skeleton into our own app on the ShardBrowser launcher fork, with a small Playwright-like automation layer in Rust, and port Breeze Blue (email route) end to end so it reaches live-run parity with the Python app.

**Architecture:** Everything of ours lives in `src-tauri/src/creator/` (Rust) and `src/creator/` (TS). Upstream files are touched only at marked seams (`// creator fork seam`) that a script verifies after every upstream merge. Automation runs in-process: the launcher starts a profile with CDP, chromiumoxide 0.7 connects, locators resolve through the CDP `Accessibility` domain plus isolated-world JS, and all pointer/keyboard input goes through the engine's hidden `Motion` domain (upstream `sdks/rust` wrappers).

**Tech Stack:** Rust (Tauri 2, tokio, chromiumoxide 0.7, upstream `shardx` crate from `sdks/rust` with feature `control`, rusqlite 0.32 bundled (already upstream), reqwest 0.12 (already upstream), axum 0.7 (already upstream, test servers only)), React + TS (upstream UI kit).

**Spec:** this document's Context section, `SPIKE-REPORT.md` (branch `creator-spike`), and the Python app `ghidorah-creator` (read-only, the source of truth for behaviour): `ghidorah_creator/providers/{breezeblue,tts_base,ele,outlook,overlays,chatgpt}.py`, `browser/{session,shard_session,cf,mouse}.py`, `engine/{account_service,platforms,errors}.py`, `proxy/assign.py`, `store/schema.py`, tests `tests/test_{breezeblue,tts_base,ele}.py`.

## Global Constraints

- Push to `origin` (public, D6) only on the owner's word; upstream is fetch only. The repo is public: no hosts, IPs, user names, personal emails or internal service addresses in committed files.
- Upstream files change only at seams carrying the marker `creator fork seam` (Rust/TS comment, or a JSON/TOML key named in the seam list). Every new seam is added to `scripts/creator/seams.json` in the same commit.
- `mod creator;` stays on `src-tauri/src/lib.rs` line 2; new Tauri commands never touch `generate_handler!` again: they are `cmd` values of `creator_call`.
- New Rust dependencies go only in the trailing `# creator fork seam` tables of `src-tauri/Cargo.toml`. chromiumoxide is pinned to the same minor as `sdks/rust/Cargo.toml` (0.7 today). `Cargo.lock` is regenerated, never hand-merged.
- Need a private upstream item? Copy it (<= 20 lines) into `creator/` before widening its visibility; a widened item is a seam.
- Repo files, docs, comments, commit messages: English. Commit messages: no AI mention, no `Co-Authored-By`.
- Never in a log line, event, error text or screenshot name: email address, password, verify link/code, API key, Ele token/API key, proxy password, cookies.
- All input to pages goes through `Motion` (no `Input.dispatch*`, no JS `el.click()` except where Python does exactly that: a covered submit button, `tts_base._submit`).
- Behaviour, texts, timings and error strings come from the Python code; where this plan quotes a value it is copied from there.
- **UI follows ShardBrowser's design entirely** (owner requirement 2026-11-22): `@proxyshard/shardx-ui-kit` components, `src/shared/ui` and `src/widgets` patterns, Shard's layout (sidebar `PageItem`, `PageHeader`, list + toolbar + bulk bar + peek), its tokens/theming (no custom colours or CSS files; upstream `check:classes`, `check:contrast`, `check:colors` stay green), its i18n pattern (keys by name, our own dictionary), its empty/loading/error states (`EmptyState`, `LoadingRows`, `LoadError`), toasts (`ToastHost`) and confirms (`ConfirmHost`). Nothing from the Python pywebview UI is ported as markup or CSS; only its features and copy carry over. Reuse a Shard widget by importing it; copy it into `src/creator/` only when it cannot take our data, and say so in the commit.
- No UI beyond the M0 smoke page is built before the owner approves the MD mockups.

## Review Focus

1. **Updates from our repo only** (D6): the updater endpoint, its key and the launcher's release repo never point at upstream. Pinned by `creator::tests::updates_come_from_our_repo`.
2. **A hidden duplicate before the visible element** (sites render desktop + mobile copies): `first_visible` must skip it; `first` must not. Pinned in Task 6.
3. **The browser freezing mid-run**: every page call is bounded; 3 timed-out polls mark the page hung and the run ends with `Browser stopped responding`, never an endless wait. Pinned in Task 5.
4. **Secrets in logs**: a full Breeze run on fixtures must leave no email/password/link/key in events, errors or `step_note`. Pinned in Task 12.
5. **A run interrupted half-way (app closed, profile crashed)**: the mailbox row and the profile id are stored before anything can fail, so a rerun reuses them (Python's `store_id` before start, password saved before the run). Pinned in Task 11.
